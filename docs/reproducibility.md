# Evidence, provenance, and reproducibility scope

## Included material

`artifact/` contains the unpacked numerical content of `finalaistats_reproducibility.zip`, including nine retained component directories, earlier study results, scientific configurations, archived training code, and all 66 training logs. The repository adds readable navigation, complete experiment implementations and their script dependencies, new public-data preparation, a local training entry point, a submitted-paper output map, and CI.

The archive contains 1,556 files. The repository omits its 13 generated TeX-row files and adjusts `artifact/PACKAGE_SHA256.json` to cover the 1,542 originally hashed files that remain. The original manifest is preserved as `provenance/original_package_sha256.json`. Scientific measurements and component code are otherwise copied byte-for-byte; Git attributes preserve their bytes across operating systems. The ZIP's SHA-256 and every omitted filename are in `provenance/repository_origin.json`.

The attached submitted PDF differs from the local workspace PDF. Its SHA-256 is retained for version identification. The root output map uses the attached submission's nine tables/five figures; the archive also rebuilds a supporting size-decision table. Original archive guides are preserved and retain their older numbering.

## What the default command verifies

`python reproduce.py` independently recalculates summaries, paired inference, finite-reference corrections, size decisions, exact population moments, directional overlap from saved covariance blocks, and all submission plots. The underlying archive validates empirical rows against `EXPECTED_RESULTS.json`, which supplies comparison fixtures rather than generated measurements. The root exports seven submitted empirical tables and two definition tables, with no missing entries in that inventory.

Table 3 is independently recalculated from full/half reference forecasts and twenty A/B outcome records, then cross-checked against the full smoothing-sweep summarizer. Appendix E checks include rare/unseen query percentages, the saved synthetic decomposition, and paired smoothing results. Top-k replay uses per-chunk hit rates, not reconstructed target ranks.

All results are computed locally and written into ignored output directories. Publication-format PDF/TeX files may be generated by the numerical scripts but are never tracked or pushed.

## What needs additional work or inputs

| Stage | Default offline rebuild | Requirements for a new run |
|---|---|---|
| Numerical aggregation, intervals, table/figure export | Executed | Analysis environment only |
| Synthetic A/B simulation | Saved-outcome comparisons recalculated | CPU simulation runners |
| Source acquisition and tokenization | Not executed | Dataset/tokenizer downloads and local storage |
| New real-text count forecasts | Not executed | Source-disjoint token arrays and frozen auxiliary/evaluation context |
| Neural inference | Not executed | Reproduced or independently obtained weights and matching inputs |
| Neural training | Not executed | CUDA GPU and complete prepared training inputs |
| Historical CPU/GPU rescore audits | Supplied as records | Original checkpoints and exact input selections |

The new public-data command creates source-disjoint matched/correction allocations and records current immutable revisions. Historical upstream downloads did not pin every revision. Exact original reconstruction is possible only when recovered inputs match the retained identities; complete historical source rosters and full position arrays are not all delivered. New allocations, GPU kernels, or software can change the results.

The original correction/confirmation timing and known-outcome status must remain visible: multiplier transfer, added bootstrap confirmation, and several policy comparisons reuse existing outcomes. The alpha sweep uses existing pairs and reference banks, with new-alpha forecasts saved before new-alpha scoring. These are not additional independent replications.
